# ViiB MediaHub v1.0.0-rc9

Release candidate 9 adds compressed stem playback and improved stem discovery, repairs Windows icons, and upgrades the desktop framework to **Wails 2.17.0**. This is a prerelease for validation.

## Changes since RC8

- **Compressed stems:** MP3 and Ogg/Vorbis stem packages validate and play through the backend decoder. Packages declare `compressed-stems-v1`, hash encoded files, and validate exact decoded geometry. WAV remains supported. ([#156](https://github.com/ajbergh/ViiB-MediaHub/pull/156))
- **Stem Library discovery:** Nested packages, four-stem compatibility, source-identity reconciliation, and background startup scans are supported. Use **Scan Stem Libraries** for a manual refresh. Ordinary music scans exclude `.viibstems` contents. ([#157](https://github.com/ajbergh/ViiB-MediaHub/pull/157))
- **Windows icons:** Correct tray icon corruption and application icon packaging. ([#158](https://github.com/ajbergh/ViiB-MediaHub/pull/158))
- **Desktop framework and dependencies:** Upgrade Wails and its pinned CLI from 2.11.0 to 2.17.0, repair dependency restoration, and update npm dependencies to resolve recorded audit findings. The Go baseline remains 1.26.10. ([#159](https://github.com/ajbergh/ViiB-MediaHub/pull/159), [#160](https://github.com/ajbergh/ViiB-MediaHub/pull/160))
- **Documentation:** Refresh repository documentation and correct source comments. ([#161](https://github.com/ajbergh/ViiB-MediaHub/pull/161))

## Web/browser packages

Choose `ViiB-MediaHub-1.0.0-rc9-web-<platform>.zip` for Windows x64/ARM64, macOS x64/ARM64, or Linux amd64/arm64. Each archive includes an executable that serves the bundled frontend locally in a browser. On Linux without Ayatana AppIndicator support, use `-no-tray`. Linux desktop packages require compatible GTK/WebKitGTK 4.1 libraries.

## Verification and known limitations

- Windows tests on the Wails 2.17 build and stem operation were reported passing by the maintainer. Native macOS/Linux interaction qualification remains open; cross-platform build success does not establish native playback or installation acceptance.
- macOS DMGs are ad-hoc signed, not Apple-notarized; Gatekeeper may require **Open Anyway**. Windows signing depends on configured credentials.
- Native second-launch activation can fail with an occupied-port error instead of raising the existing window. Native bundle/runtime version metadata may show `1.0.0` or development defaults; use the downloaded package name and release checksum to identify this candidate.
- FLAC/M4A backend DJ analysis remains unsupported; playback and client waveform decoding depend on the browser/WebView decoder.
- Hardware/controller routing, professional analysis accuracy, authenticated provider coverage, and assistive-technology qualification remain open. RC9 does not imply stable 1.0 qualification.
- Back up your local library data before upgrading. Keep RC8 available for rollback and report regressions in [Issues](https://github.com/ajbergh/ViiB-MediaHub/issues).
