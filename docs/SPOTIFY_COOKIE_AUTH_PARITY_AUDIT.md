## Proxy and credential export gates (2026-10-04)

The generic non-catalog proxy now rejects request bodies above 2 MiB before dispatch and bounds successful JSON responses to 8 MiB. Malformed, empty, trailing or oversized success payloads produce a redacted 502 rather than a fabricated `null` success. HTTP 204/304 and HEAD retain empty-body semantics. Provider failures retain HTTP status and normalized 429 Retry-After, with redacted error bodies. Fixture transport tests cover 403/404/429 without disconnecting the cookie session, active-request cancellation, origin/cookie isolation and oversized-input rejection. This verifies the failure contract; it does not establish successful live write-route parity.

Generic settings deny both reads and writes of the session setting while ordinary settings still work. Support-bundle fixtures include cookie key/value, JSON, header and query forms and a stored encrypted session. New backup archives remove `spotify_webplayer_session` and `spotify_credentials` from a consistent temporary database copy, erase deleted credential bytes with SQLite secure_delete/VACUUM, then hash/archive the sanitized copy. The fixture inspects the actual ZIP database, checks both rows and encrypted/raw credential bytes are absent, and confirms ordinary settings and the live source credentials remain intact. Restoring a new archive requires Spotify sign-in. Existing archives are not modified, and other integration credentials retain their previous backup behavior.
