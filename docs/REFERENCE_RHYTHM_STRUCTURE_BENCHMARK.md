# Rhythm and structure reference benchmark

This harness is development-only. It emits raw third-party rhythm/structure
predictions and provenance as JSON; it does not add model code, weights, or ML
runtime to MediaHub. Beat This and All-In-One remain isolated external
processes. Their results are diagnostic unless the corpus and model training
overlap are reviewed.

## Shared result contract

All adapters emit `schema: "viib.rhythm-reference.v1"` with:

- `configuration`: exact tool/model/version, checkpoint identity when
  available, split, manifest hash, runtime choices and license note;
- `audioTiming`: per-track WAV identity, source audio hash, ViiB decoder
  version, channels/rate/frames, timeline origin, declared trim and resample
  delay, decoded PCM hash, and the complete WAV file hash;
- `results`: one row for every track in the requested split, including
  failures and blocked rows.

Each successful row has `rhythm.tempoBpm`, `rhythm.beats` and
`rhythm.downbeats`, with timestamps in seconds from ViiB's decoded source frame
zero. Beat and downbeat events may carry confidence in `[0,1]`. An external
model's emitted downbeat is marked `measured` with
`provenanceScope: "benchmark-reference-prediction"`; this describes the
prediction source and does not promote it to production rhythm-grid state.
Manually confirmed annotations use `manual`; a placeholder calculated from
meter uses `inferred-from-meter`. Unknown provenance stays `unknown`. Meter,
meter confidence and native/mapped structure labels remain separate optional
fields. Legacy `bpm`,
`beatPositions`, and `downbeatPositions` fields are included for the existing
BPM comparison tooling.

`configuration.split` records `tuning` or `held_out` separately from each
track's `evidenceClass`: `training-overlap-contaminated`,
`overlap-reviewed-clear`, or `overlap-unreviewed`. Contamination never changes
the split assignment. Do not combine contaminated rows with clean held-out
qualification metrics.

## Canonical ViiB timing input

The adapter must not independently decode MP3/AAC or any other source. Create
the input WAV with `backend/cmd/canonicalwav`, which uses MediaHub's production
decoder, bounded mono downmix and native sample rate. It returns
`canonicalWavPath`, `pcmSHA256` and the `canonicalAudio` object used by the
manifest:

```bash
cd backend
go run ./cmd/canonicalwav \
  -input '/private/audio/source.mp3' \
  -output '/private/research/canonical/track.wav' \
  > '/private/research/canonical/track-timing.json'
```

Copy the helper's `canonicalWavPath` and `canonicalAudio` fields into the
corresponding manifest track. The helper writes mono PCM16 at the source
decoder's native sample rate with no resampling or trim. A manifest track is
usable only when it supplies these generated fields:

```json
{
  "id": "track-id",
  "split": "tuning",
  "artist": "Artist",
  "title": "Track",
  "path": "original/source.mp3",
  "canonicalWavPath": "canonical/track.wav",
  "canonicalAudio": {
    "decoder": "ViiB",
    "decoderVersion": "go-mp3-v0.3.4",
    "encoding": "pcm_s16le",
    "channels": 1,
    "sampleRate": 44100,
    "frames": 9876543,
    "sourceAudioSHA256": "<SHA-256 of interleaved WAV data chunk bytes>",
    "timelineOriginSeconds": 0,
    "resampleDelaySamples": 0,
    "startTrimSamples": 0
  }
}
```

The validator checks the actual RIFF/WAVE format tag, bit depth, channel
count, sample rate, block alignment and frame count against this metadata. It
accepts PCM16 and IEEE float32 WAV, mono or stereo. Missing metadata yields a
`blocked` result with `canonical_audio_unavailable`; malformed or mismatched
WAV metadata also blocks that row. `sourceAudioSHA256` is SHA-256 over the raw
interleaved `data` chunk bytes (PCM16 or IEEE float32), and the adapter verifies
that digest against the WAV. This is the decoded-audio identity, distinct from
the separately recorded full-container WAV hash. `resampleDelaySamples` and
`startTrimSamples` must both be zero because no timestamp remapping is
implemented. The adapter does not apply an offset. WAV timestamps therefore
retain the timeline origin declared by the ViiB Go decoder. Do not fill in a decoder identity or
timing values from assumptions; the metadata is a contract for a future decode
exporter, not information already generated by MediaHub today.

## Training overlap audit

`scripts/training_overlap_audit.py` accepts flattened JSON annotation records
or CSV with `artist` and `title` columns. It performs exact, Unicode-normalized
artist/title matching and never uses fuzzy matching. Aliases, remasters, live
recordings and spelling variants can be missed. It marks unmatched tracks
`overlap-unreviewed` unless `--coverage-complete` explicitly attests that the
supplied annotations cover the named model training corpus.

Example:

```bash
python scripts/training_overlap_audit.py \
  --manifest 'sample_media/Test Corpus/phase0-spotify-manifest-r5.json' \
  --annotations '/private/research/beat-this-v1-annotations.csv' \
  --model 'beat-this final0 / version and checkpoint hash' \
  --training-corpus 'Beat This annotations v1.0' \
  --coverage-complete \
  --out '/private/research/beat-this-r5-overlap-audit.json'
```

The audit records the manifest and annotation-file hashes plus matched training
record identifiers. Pass its report as `--overlap-audit` to either adapter.
The adapter verifies that the audit used the exact manifest bytes and has the
same track IDs before applying per-track evidence classes. Without a supplied
report, rows stay `overlap-unreviewed`.

## Beat This adapter

The existing `scripts/beat_this_bpm_benchmark.py` runs Beat This `final0`
with the local checkpoint and CPU minimal postprocessor. The adapter stores
the model's raw beat/downbeat timestamps and derives the BPM scalar using the
median of 16-beat spans. It does not fetch checkpoints. Its isolated
environment is described in
[`REFERENCE_BPM_BENCHMARK.md`](REFERENCE_BPM_BENCHMARK.md).

```bash
python scripts/beat_this_bpm_benchmark.py \
  --manifest '/private/research/canonical-r5.json' \
  --path-base '/private/research' \
  --checkpoint '/private/models/beat-this-final0.ckpt' \
  --overlap-audit '/private/research/beat-this-r5-overlap-audit.json' \
  --split tuning \
  --out '/private/research/beat-this-r5-tuning.json'
```

Held-out runs still require `--allow-held-out`. Beat This training data
contains Harmonix, which overlaps the ViiB r5 corpus; the already documented
r5 measurements remain contaminated diagnostics, not independent
qualification evidence.

## All-In-One-Infer adapter

`scripts/allinone_structure_benchmark.py` uses the documented
`allin1_infer.analyze(paths=..., model=...)` API and records tempo, beats,
downbeats, beat positions in bar and native functional segment labels. It
does not remap `break`, `inst` or `solo` to ViiB labels. All-In-One-Infer may
download model weights when they are absent from its cache; the adapter
therefore refuses to start unless `--allow-model-download` is passed. Review
the model and transitive runtime licenses in the isolated environment. The
documented API identifies weights by model registry name but does not expose a
resolved checkpoint path/hash; the output records that limitation explicitly.
For qualification-grade results, add a verified checkpoint hash once upstream
exposes or the adapter can safely identify the exact local artifact.

Install the pinned package into an isolated environment, review its transitive
dependencies and model terms, then run the example above with that environment's
Python:

```bash
python3 -m venv /tmp/viib-allinone-venv
/tmp/viib-allinone-venv/bin/pip install -r tools/reference-allinone-requirements.txt
```

```bash
python scripts/allinone_structure_benchmark.py \
  --manifest '/private/research/canonical-r5.json' \
  --path-base '/private/research' \
  --model harmonix-fold0 \
  --overlap-audit '/private/research/all-in-one-r5-overlap-audit.json' \
  --split tuning \
  --allow-model-download \
  --out '/private/research/all-in-one-r5-tuning.json'
```

An independent evaluation needs a complete Harmonix training annotation export
and an overlap audit; the shared training set makes exact and possible
metadata variants particularly important. No All-In-One predictions are
recorded until the package, model weights and canonical WAV artifacts are
available locally.

## Current local execution blockers

In the reviewed environment, Python cannot import `beat_this`, `torch`,
`torchaudio` or `allin1_infer`; no Beat This checkpoint was present in the
expected torch checkpoint cache. FFmpeg is installed but is not used by these
adapters because a second decoder would violate the ViiB timeline contract.
The `canonicalwav` Go helper is now available, but no canonical WAV artifacts
or Python model runtimes/checkpoints have been generated/installed in this
workspace. The harness and raw result contract are ready, but there are no new
model predictions to report.
